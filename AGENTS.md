# Aurex Business Labs project rules

## Brand and content

- The public brand name is Aurex Business Labs. Never use Aurex Agency in visible content.
- Be clear, direct, practical, locally grounded, and business-focused.
- Do not use em dash characters in copy, code comments, metadata, or documentation.
- Never fabricate testimonials, ratings, customer counts, performance metrics, awards, or scarcity.
- The core positioning is customer acquisition and revenue systems for established residential contractors. Preserve the Aurex Revenue Capture System, Capture / Convert / Recover / Compound method, results and Revenue Leakage Audit. Do not publish pricing, payment schedules, investment-readiness questions, discounts, capacity scarcity or monetary launch assurances.
- Financial proof and client media require both verified status and publication permission in src/lib/proof.ts.
- Approved portfolio examples: Norton Equipment Co, Triple R Trailers, Wood Eye Clinic, and NetTech.

## Design and behavior

- Shared palette and responsive styles are in src/app/globals.css, one design system with tokens on :root and l- (shared) and f- (homepage field guide) class prefixes. Midnight #070C13, cool white #F0F6FA, Aurex cyan-blue #19BCE5, and pale blue #8BDFF6 are the primary tokens. Headlines use Geist; Instrument Serif italic is reserved for accent phrases in em. Use sentence case for headings.
- Geist is the body font. Instrument Serif is for selected editorial emphasis.
- Preserve the official blue symbol with the Business Labs wordmark. The original Agency lockup is a source asset, not the public wordmark.
- The public site is an educational contractor field guide with varied editorial compositions, midnight and pale-blue surfaces, and original contractor-journey motion graphics. Resources and lessons are the primary journey; the audit is secondary. Use motion/react with the shared LazyMotion provider. Retain complete static content.
- Respect reduced motion and keep the full message available without animation. Entrance motion is gated by data-motion on the root and the reveal observer, so content is never hidden without scripts. Keep the largest heading visible from the first frame. Mobile uses stacked system content with the journey timeline.
- The atmosphere layer (src/components/landing/ambient.tsx), hero light field (light-field.tsx), homepage journey line (src/components/learn/journey-line.tsx) and inner page hero scenes (src/components/authority/hero-scenes.tsx) are decorative and aria-hidden. Keep them behind content, paused off screen, and still under reduced motion. Do not use React ViewTransition for route changes: it caused intermittent hydration errors under load. Route entrances use src/components/landing/route-sweep.tsx and play only after the first page load.
- Trades shown in the homepage band and the audit form come from src/content/trades.ts. The /call application uses the trade list in src/lib/funnel.ts.
- /call is the paid ads funnel: headline, video, application, trust strip, one-line footer. Do not add navigation, FAQ, pricing, portfolio, testimonials walls, chat, popups or timers. It stays noindex and out of publicRoutes. Routing rules and CRM tags live in src/lib/funnel.ts and are decided on the server. Meta Lead fires only for qualified and borderline applicants and Schedule only on /call/booked; nothing fires on the disqualified path. Keep zod out of the funnel client bundle. See docs/ADS_FUNNEL.md.
- Maintain WCAG 2.2 AA expectations, keyboard navigation, focus visibility, error associations, and at least 44px practical touch targets.

## Source organization

- src/content/work.ts and articles.ts contain reusable project and editorial content. src/lib/site-config.ts owns company configuration. src/lib/proof.ts owns evidence and permission gates.
- Legacy website-offer source is archived in docs/archive; its supporting copy and assets are retained.
- src/components/learn contains the educational graphics, resource library, scorecard and checklist. src/content/resources.ts owns shared lesson content and downloads are generated by scripts/build-resources.mjs. src/components/studio retains portfolio motion and the contact form. src/components/authority contains shared chrome and editorial sections. src/components/landing retains shared attribution, analytics and motion utilities.
- src/lib/lead-schema.ts owns client/server validation. src/app/api/leads/route.ts owns delivery.
- The root is the educational contractor homepage. /start-here, /resources and /resources/[slug] are the main learning paths. /contractor-revenue-scorecard is an evergreen entry to the free scorecard. /revenue-capture-system, /results and /apply are active routes. /approach and /revenue-website redirect to /revenue-capture-system. The old thank-you URL redirects to /apply. Audit and contact submissions confirm only after delivery.
- Read relevant Next.js documentation from node_modules/next/dist/docs before changing framework behavior.

## Configuration and verification

- Keep GHL_WEBHOOK_URL server-only. Never commit actual secrets or log production personal information.
- Missing or failed production webhook delivery must return an error, never simulated success.
- LEAD_DEV_MODE=true allows redacted local simulation only outside production.
- Analytics must remain disabled without IDs. Conversions require confirmed submission, not a page view.
- Run npm run lint, npm run typecheck, npm run build, npm run test:e2e, npm run test:a11y, and npm run test:api.
- Set PLAYWRIGHT_BASE_URL to test an existing production server. Browser tests use the approved GA4 ID explicitly, with GTM/Ads/Meta IDs and GHL/Zoom embed URLs unset. Analytics has no default enabled IDs. Google requests are intercepted so tests cannot send analytics traffic. The calendar and embed script are stubbed during regression tests. With the live webhook in .env.local, use a separate test server started with GHL_WEBHOOK_URL= on port 3002 to prevent test leads from reaching GHL.
- Capture and inspect requested viewport screenshots in artifacts/. Do not publish test artifacts.
- agentRules is disabled in next.config.ts so framework-generated prose does not reintroduce prohibited punctuation. Maintain this document manually.
